# 发布与自动更新

> Sparkle 已接入（2.9.6，SPM）；`检查更新…` 菜单与更新框架可用。
> 当前 `SUFeedURL` / `SUPublicEDKey` 是占位值，真正发布前必须替换。

## 1. 前提

- Apple Developer Program（$99/年）
- Developer ID Application 证书
- App 专用密码（appleid.apple.com → 安全 → App 专用密码）

## 2. 签名

在 Xcode 或命令行使用 Developer ID Application：

```bash
codesign --deep --force --options runtime --timestamp \
  --sign "Developer ID Application: Your Name (TEAMID)" Liteshot.app
```

## 3. 公证

```bash
ditto -c -k --keepParent Liteshot.app Liteshot.zip
xcrun notarytool submit Liteshot.zip \
  --apple-id "$APPLE_ID" --password "$APP_PASSWORD" --team-id "$TEAM_ID" --wait
xcrun stapler staple Liteshot.app
```

## 4. Sparkle 密钥

1. 从 Sparkle 包内运行 `bin/generate_keys`
2. 把输出的公钥填到 `project.yml` 的 `SUPublicEDKey`
3. 私钥保存在钥匙串，`generate_appcast` 会用它签名更新

```yaml
SUFeedURL: "https://your-domain/appcast.xml"
SUPublicEDKey: "<generate_keys 输出的公钥>"
```

## 5. 生成 appcast

```bash
SPARKLE_BIN=/path/to/Sparkle/bin
"$SPARKLE_BIN/generate_appcast" build/release
```

把 `appcast.xml` 和 zip 上传到 `SUFeedURL` 对应目录。

## 6. 一条命令

`scripts/release.sh` 串好了 archive → 签名 → 公证 → staple → appcast：

```bash
export TEAM_ID=...
export APPLE_ID=...
export APP_PASSWORD=...
export SIGN_IDENTITY="Developer ID Application: ..."
export SPARKLE_BIN=/path/to/Sparkle/bin
VERSION=0.2.0 BUILD=2 ./scripts/release.sh
```

## 7. 自更新测试

1. 安装旧版本到 /Applications
2. 发布新版本 zip + appcast
3. 菜单「检查更新…」→ Sparkle 应提示新版本
4. 注意：未签名的开发版会因签名校验失败而无法更新，这是预期行为

## 8. 常见问题

- **更新错误**：feed 不可达或公钥不匹配。先用 `curl` 确认 appcast 可访问。
- **公证失败**：检查 Hardened Runtime 是否开启、是否带时间戳、嵌入式 Sparkle.framework 是否一起签名。
- **TCC 权限被重置**：每次更换签名身份都会重置屏幕录制授权，发布前用固定证书。
