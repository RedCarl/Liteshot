# 发布与更新

Liteshot 有两条分发渠道：

- **Mac App Store（主渠道）**：bundle id `cn.carljoy.liteshot`，由 App Store 审核并推送更新。
- **GitHub Release（源码构建包）**：ad-hoc 签名、未公证的 zip / dmg，给想直接用最新源码的人；首次打开需要在 Finder 里右键 →「打开」。

## 发版

1. 改 `project.yml` 里的 `MARKETING_VERSION`（必要时也加 `CURRENT_PROJECT_VERSION`），同步 `CHANGELOG.md`
2. `xcodegen generate`
3. 需要上架时：归档并上传 App Store Connect（见下）
4. 需要发 GitHub Release 时：`scripts/release-github.sh` 产出安装包，再 `gh release create`

## App Store

```bash
xcodebuild archive \
  -project Liteshot.xcodeproj -scheme Liteshot \
  -destination 'generic/platform=macOS' \
  -archivePath build/Liteshot.xcarchive \
  -allowProvisioningUpdates DEVELOPMENT_TEAM=BCRZR3P4AP

xcodebuild -exportArchive \
  -archivePath build/Liteshot.xcarchive \
  -exportOptionsPlist /tmp/upload.plist \
  -exportPath dist-upload -allowProvisioningUpdates
```

其中 `upload.plist` 用 `destination = upload`、`method = app-store-connect`，直接走 Apple 的上传通道。上传后在 App Store Connect 补齐版本信息、截图，提交审核；审核通过后由 App Store 分发。

## GitHub Release

```bash
scripts/release-github.sh          # 产出 dist/Liteshot-<版本>.dmg 和 -macOS.zip
gh release create v1.0.1 \
  dist/Liteshot-1.0.1.dmg dist/Liteshot-1.0.1-macOS.zip \
  --title "Liteshot 1.0.1" \
  --notes-file <(sed -n '/## 1.0.1/,/## 1.0.0/p' CHANGELOG.md | sed '$d')
```

- 包是 ad-hoc 签名（`codesign --force --deep --sign -`），没有 Developer ID 证书、也没做公证，Gatekeeper 会要求右键打开
- 应用不联网、不检查更新，GitHub 渠道的更新只能手动下载覆盖
- Release 由本机脚本产出，CI 只做编译与自检，不签名、不发布

## 更新

App Store 渠道由 App Store 推送；GitHub 渠道手动下载覆盖安装。

## CI

- `.github/workflows/build.yml`：每次 push 编译 + 跑自检，不产出分发包
- `.github/workflows/pages.yml`：部署 `site/` 到 GitHub Pages

## 签名

- App Store 分发证书：`Apple Distribution`（Xcode 云托管，私钥在苹果服务器，本机钥匙串里看不到）
- GitHub Release：ad-hoc 签名，只为了让 TCC 按 bundle id 记录权限，不是身份凭证
- 团队：`BCRZR3P4AP`
- 沙盒与权限写在 `Resources/Liteshot.entitlements`；`com.apple.security.files.pictures.read-write` 在 macOS 上不被支持，已移除

## 历史

仓库 0.3.x 时期发过 ad-hoc zip，后来为专心走 App Store 移除了工作流、清理了标签和 Release；1.0.1 起以 GitHub Release 形式恢复，与 App Store 并行。
