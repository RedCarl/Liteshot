# Liteshot 技术选型（macOS 截图工具）

> 目标：聚焦截图主线（区域 / 窗口 / 全屏 / 延迟 / 标注 / 保存），砍掉录屏、测量、订阅体系等支线，做一个轻量、原生、启动即用的 macOS 菜单栏截图工具。

---

## 1. 结论

**原生 macOS：Swift 6 + SwiftUI（壳/设置）+ AppKit（覆盖层/画布）+ ScreenCaptureKit（采集）。最低 macOS 14。**
不上 Electron / Tauri，除非明确要 Windows 版。

理由只有三条，但都是决定性的：

1. **截图工具的核心体验由系统 API 决定**：屏幕采集、TCC 权限、多屏坐标、全屏覆盖窗口、全局快捷键，原生一条链全通；跨端方案每一环都要写平台桥接，且很难稳定。
2. **选区覆盖层需要“像素级控制”**：透明全屏窗口跨屏、`.screenSaver` 层级、鼠标穿透、Retina 坐标换算、实时放大镜，这些用 AppKit 直接做，Web 方案要靠 hack。
3. **体积与冷启动**：原生 App 约 5–10 MB、冷启动百毫秒级；Electron 100 MB+，截图工具用户对“点一下要等两秒”极度敏感。

代价：只支持 macOS；需要写 Swift。对一个 macOS-only 的小工具，这个代价是划算的。

## 2. 技术栈总表

| 层 | 选型 | 说明 / 替代 |
|---|---|---|
| 语言 | Swift 6（严格并发） | 与系统框架零胶水 |
| App 壳 | `LSUIElement` 菜单栏 App，`NSStatusItem` + `NSMenu` | SwiftUI `MenuBarExtra` 可用，但自定义面板/右键菜单受限，建议 AppKit 管理状态栏 |
| 设置/关于页 | SwiftUI + `NSHostingView` | 表单类界面 SwiftUI 效率最高 |
| 采集 | **ScreenCaptureKit**（`SCScreenshotManager.captureImage`，macOS 14+） | 兜底 `CGWindowListCreateImage`（已废弃但可用）；不要拿 `screencapture` CLI 上生产 |
| 窗口枚举 | `SCShareableContent.excludingDesktopWindows` | 拿 `SCWindow` 做“点选窗口” |
| 选区覆盖层 | AppKit：每块屏一个无边框 `NSWindow`（`level = .screenSaver`，`collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]`）+ 自绘 `NSView` | 不用 SwiftUI 全屏遮罩，层级/跨屏/鼠标事件都不可控 |
| 放大镜 / 取色 | 选区开始时先抓一张全屏位图，覆盖层只做采样与放大 | 避免鼠标移动时反复抓屏（掉帧、闪烁） |
| 标注画布 | AppKit `NSView` + Core Graphics 绘制，元素用值类型模型 | SwiftUI `Canvas` 可做 MVP，但命中测试、1px 对齐、文字排版后期会卡住 |
| 文字标注 | `NSAttributedString` + Core Text | 描边/阴影用 `NSAttributedString` 的 stroke 属性 |
| 马赛克/模糊 | Core Image（`CIPixellate` / `CIGaussianBlur`）+ 区域蒙版 | 六边形马赛克需自绘 |
| 导出 | ImageIO（`CGImageDestination`）输出 PNG/JPEG，`kCGImagePropertyDPI*` 写 Retina 元数据 | 不要用 `NSImage` 截图往返，会丢色/丢精度 |
| 全局快捷键 | [KeyboardShortcuts](https://github.com/sindresorhus/KeyboardShortcuts)（SPM，MIT） | 底层是 Carbon `RegisterEventHotKey`，**不需要辅助功能权限**；比 CGEventTap 干净 |
| OCR | Vision `VNRecognizeTextRequest`（`zh-Hans` + `en-US`） | 全本地、免费、无需联网；识别结果可直接进剪贴板 |
| 二维码 | Vision `VNDetectBarcodesRequest` | 与 OCR 共用一张图，几乎没有额外成本 |
| 滚动截图 | ScreenCaptureKit `SCStream` + 帧间重叠匹配（Accelerate vImage / `VNTranslationalImageRegistrationRequest`） | 全项目风险最高的一块，放 v0.3 |
| 设置持久化 | `UserDefaults` + `Codable` 配置结构 | 键名独立命名空间，方便导入导出 |
| 文件命名模板 | 自写 token 解析（年/月/日/时/分/秒/序号/随机串） | 不用格式化库 |
| 构建 | XcodeGen 生成 `.xcodeproj`，Xcode 27 构建（本机已跑通） | 也可纯 SwiftPM + 手工打 `.app`，但签名/权限调试麻烦 |
| 分发 | GitHub Actions 构建 + Releases 下载；可选 Developer ID 签名 + notarytool 公证 | MAS 版本后期再说：沙盒下保存路径要 security-scoped bookmarks |
| 测试 | XCTest（坐标换算、命名模板、拼接算法用固定帧回放） | 覆盖层交互靠手动 |

依赖就一个：`KeyboardShortcuts`。其余全是系统框架。

## 3. 为什么不是 Electron / Tauri / Flutter

| 方案 | 结论 | 原因 |
|---|---|---|
| Electron | 不推荐 | 包体 100 MB+；透明覆盖层跨屏层级难控；采集要么调 CLI 要么写 native addon，等于还是写 Swift |
| Tauri 2 + Rust | 可选，次优 | 包体小、Web 画布写标注很舒服；但 macOS 采集/覆盖层/权限仍要 `objc2` 写平台层，工作量≈原生 + 前端，且滚动截图拼接生态弱。只有当 **Windows 是硬需求** 时才值得 |
| Flutter Desktop | 不推荐 | 桌面截图插件生态差，覆盖层和 TCC 权限都要自己写 platform channel |
| Python + PyObjC | 仅验证想法 | 打包、签名、分发给用户都痛苦 |

如果未来真要跨平台：核心（采集 + 拼接 + 标注渲染）留 Native，UI 抽出来，这比一开始选 Tauri 再拆更省事。

## 4. 关键实现路径

### 4.1 截图管线

```
热键/菜单 → 权限检查 → 抓当前显示器整帧（像素尺寸）
        → 覆盖层展示 + 交互选区（点/拖/方向键微调）
        → 按 scale 裁剪 → 抠出 CGImage
        → [可选] 阴影/圆角 → 进编辑器 或 直接写剪贴板/存盘
```

- **区域截图**：先整屏抓一张再裁。比“按选区建 filter 再抓”稳，免去坐标系来回换算，还能给放大镜复用。
- **窗口截图**：`SCContentFilter(desktopIndependentWindow:)`；注意它**不含窗口阴影**，阴影要自己用 Core Graphics 合成（或用 `CGWindowListCreateImage(.optionIncludingWindow)` 再补阴影）。
- **Retina**：所有几何先按 point 算，最后乘 `NSScreen.backingScaleFactor` 取像素；`SCStreamConfiguration.width/height` 必须给像素值。
- **多屏**：`NSScreen.screens` 每块屏一个 overlay 窗口，用 `screenNumber` 映射 `CGDirectDisplayID`；窗口跨屏时以“鼠标所在屏”为主屏处理。

### 4.2 选区覆盖层（体验分水岭）

- 窗口：无边框、透明、`level = .screenSaver`、`canJoinAllSpaces`、`fullScreenAuxiliary`、`acceptsMouseMovedEvents`。
- 绘制：整屏压暗（半透明黑），选中区挖洞（`CGContext` 的 even-odd 裁剪或 `NSCompositingOperation`），选中边框 + 尺寸标签。
- 放大镜：从预抓帧取光标周围 60×60 pt，放大 8×，中心画准星，旁边实时显示坐标与色值（HEX/RGB）。
- 键盘：方向键 1px 微调（按住 Shift 10px）、`Return` 确认、`Esc` 取消、`Space` 切窗口/区域模式。
- 吸附：用 `SCShareableContent` 的窗口 frame 做候选边，距离 < 8px 时吸附（可选，v0.2）。

### 4.3 标注编辑器

- 模型：`enum Annotation { case rect, ellipse, arrow, line, pencil, text, counter, mosaic, highlight }`，每个带起点/终点/样式。
- 绘制：一个 `NSView` 里按 z 序画，`draw(_:)` 直接走 CG；马赛克先裁区域 → CI 滤镜 → 贴回。
- 交互：命中测试自己做（外接矩形 + 路径 `contains`），选中框八个手柄，方向键微调。
- 撤销：命令栈（add/move/style/delete），比 `NSUndoManager` 更好控序列化。
- 导出：离屏 CGContext 按像素尺寸重绘一遍，保证 1:1；JPEG 质量可调。
- 工具条：AppKit `NSToolbar` 或自绘横向条；先固定 6 个工具，别做自定义排序。

### 4.4 OCR / 二维码

Vision 同步请求，208ms 级别（M 系列，整屏文字），放后台 `Task.detached`。识别框可直接映射回图片坐标做“文字高亮框”，这是免费加分项。

### 4.5 滚动截图（最难，最后做）

1. 选区后建 `SCStream`（`sourceRect` = 选区，10–15 fps，只留 `CMSampleBuffer`）。
2. 用户滚动，逐帧计算与上一帧的垂直位移：先做行哈希粗筛（相同行跳过），再用 `vDSP` 相关或 `VNTranslationalImageRegistrationRequest` 求 dy。
3. 位移 < 阈值丢弃；按 dy 拼接，重叠区取平均或取上帧，避免接缝。
4. 结束条件：连续 N 帧无位移 或 用户按 Esc；输出超高图（注意 `CGImage` 高度上限与内存，必要时分段）。

失败模式必须给提示（滚动过快 / 选区不对），这是同类工具常见的坑。

## 5. MVP 范围

### v0.1（先做出来，2–4 周）

- 菜单栏常驻 + 全局快捷键（区域 `⌃⌘A`、全屏 `⌃⌘S`）
- 区域截图（放大镜、取色、方向键微调）、全屏、窗口点选
- 延迟截图（3/5/10s）
- 保存：剪贴板 / 固定目录 / 自动保存 / PNG+JPG / 文件名模板（日期+序号）
- 标注：矩形、箭头、直线、画笔、文字、马赛克（方头）
- 撤销/重做、复制、保存、Esc 取消
- Retina 正确、多屏正确、权限引导页

### v0.2（好用）

- 序号标注、高亮、圆角/阴影/透明背景
- 截图历史（缩略图列表）、上次区域、窗口多选（Shift）
- OCR + 二维码（Vision，成本极低）
- 快捷键自定义页（KeyboardShortcuts 自带录制控件）

### v0.3（差异化，可砍）

- 滚动截图（竖向优先）
- 贴图（钉在屏幕上）
- 标注工具条自定义

### 明确不做

录屏、屏幕测量、订阅/限次、URL Scheme、水印、10 种语言、GIF 贴图、AirDrop 菜单项（先只留“在 Finder 中显示”）。

## 6. 工程结构（建议）

```
Liteshot/
├── project.yml                 # XcodeGen：app target, macOS 14+, LSUIElement
├── Sources/
│   ├── App/                    # AppDelegate、StatusBar、HotkeyCenter、Settings 窗口
│   ├── Capture/                # ScreenCaptureService、SelectionOverlay、WindowPicker、CaptureCoordinator
│   ├── Editor/                 # EditorWindowController、CanvasView、Annotation 模型、Exporter
│   ├── Vision/                 # OCRService、BarcodeService
│   ├── Scrolling/              # ScrollCaptureSession、Stitcher（v0.3）
│   └── Shared/                 # Permissions、Preferences、FileNaming、Geometry、ImageIO
├── Resources/                  # Assets.xcassets、Localizable（先只 zh-Hans + en）
└── Tests/                      # 几何换算、命名模板、拼接（固定帧）
```

`project.yml` 关键项：`LSUIElement: true`、`LSMinimumSystemVersion: 14.0`、`NSHighResolutionCapable: true`、`com.apple.security.app-sandbox: false`（直发版）、关闭 Hardened Runtime 的 JIT（不需要）。

## 7. 权限与分发的坑

1. **屏幕录制 TCC**：首次调用 `SCShareableContent` 会弹系统授权；用户拒绝后必须引导去“系统设置 → 隐私与安全性 → 屏幕与系统音频录制”。改过签名/重装会重置授权 —— 开发期用固定 Team 的 Developer ID 签名，别用 ad-hoc，否则每次重新编译都要重新授权。
2. **授权后可能要求重启 App**（macOS 旧行为）；macOS 15+ 通常即时生效，但仍要处理 `SCStream` 报错分支。
3. **全局快捷键不需要辅助功能权限**（Carbon 热键），这是选 KeyboardShortcuts 而非 CGEventTap 的原因；如果以后做“取窗口文字/自动滚动”，才需要 AX 权限。
4. **沙盒**：直发版不开沙盒，保存路径自由；上 MAS 则必须开沙盒，首次保存要 `NSSavePanel` 授权并把 bookmark 存下来。
5. **公证**：`notarytool submit --wait` + `stapler staple`；更新包签名与代码签名是两套东西，别搞混。
6. **`screencapture` CLI**：仅用于 spike 验证，正式采集别用 —— 有 ~200–400ms 进程开销，且拿不到干净的窗口帧。

## 8. 风险清单

| 风险 | 影响 | 对策 |
|---|---|---|
| 滚动截图拼接不准 | 高 | 放 v0.3；先做固定场景回放测试集 |
| 覆盖层多屏/缩放坐标错位 | 高 | 几何换算集中一个 `Geometry` 模块 + 单测；所有坐标先 point 后 pixel |
| 文字标注排版（中文换行、描边） | 中 | 早期用 `NSAttributedString.boundingRect` 定框，别自己排 |
| 权限被拒后的死循环 | 中 | 明确“已授权/未授权/需重启”三态 UI |
| 大图内存（滚动长图 > 100MP） | 中 | 分块渲染 + 上限提示 |
| 上架 MAS | 低（先不做） | 直发 → 有量再评估 |
