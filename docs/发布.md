# 发布与更新

Liteshot 的发布走 GitHub Actions，不需要 Developer ID，也不做 App Store 上架。

## 发版

```bash
git tag v0.2.0
git push origin v0.2.0
```

推送 `v*` 标签后，`.github/workflows/release.yml` 会：

1. 在 macOS runner 上选择最新稳定 Xcode
2. `xcodegen generate`
3. 构建 Universal（arm64 + x86_64）Release
4. ad-hoc 签名（标识 `com.redcarl.Liteshot`）
5. 打包 `Liteshot-<version>.zip` 和 SHA256
6. 创建 GitHub Release

版本号取自标签（`v0.2.0` → `0.2.0`），构建号用 Actions 的 run number。

## 更新检查

App 菜单「检查更新…」会请求：

```
https://api.github.com/repos/RedCarl/Liteshot/releases/latest
```

有更新时展示版本号与发布说明，并打开 Release 页面供手动下载；不会自动安装。未认证请求受 GitHub 限流（每小时 60 次），个人使用足够。

## 签名与公证（可选）

当前产物只有 ad-hoc 签名，Gatekeeper 会提示未公证。自用可右键打开或：

```bash
xattr -dr com.apple.quarantine /Applications/Liteshot.app
```

如果以后要正式分发，可以：

1. 准备 Developer ID Application 证书
2. 在 CI 里导入证书，替换 ad-hoc 签名步骤
3. 用 `notarytool submit --wait` 公证并 `stapler staple`
4. 在 Release 里上传公证后的 zip

这不会影响当前的开源构建流程。

## 已知限制

- ad-hoc 签名在每次版本更新后可能让屏幕录制授权失效，需要重新勾选一次。
- 没有 Developer ID 的情况下不做自动安装，更新检查只打开 Release 下载页。
